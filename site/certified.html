The strongest copy obtainable is the certified one, and it can only be taken once. JIMS offers a Download Certified Copy button only while a certified copy is still available — once taken (by anyone), it is gone; a regular copy can be downloaded any number of times. So the capture rule is mechanical, and it is applied to every document in the library:

Why it matters: taking a regular copy while the certified button is enabled is a one-way loss of the strongest form of that document — the certified download cannot be re-obtained. A regular copy can never be turned into a certified one. That is why the policy is "certified first", and why /register and /access state each file's form (CERT / SRC / TEXT / PACK).

How each capture is traced through Windows telemetry

A file is evidence only if we can say when and from where it came. The station records this from evidence the operating system keeps independently of our notes:

  1. The bytes — SHA-256, size, and the NTFS CreationTime / LastWriteTime.
  2. Zone.Identifier — the NTFS alternate data stream Chrome writes on download. It carries the source URL and referrer, and is the closest thing to a receipt that the file came from jimspss1.courts.state.hi.us.
  3. Chrome downloads history — the live History SQLite database, queried for the file name (target path, start time, URL, referrer, received bytes, state).
  4. USN journal (where available) — survives browser-history clearing.

The record binds file → docket → JIMS URL → download time → browser row → hash, and is appended to TELEMETRY.jsonl by tools/ssot/download_telemetry.ps1. A capture without telemetry is still evidence of the file, but it cannot prove when it was taken — and "already downloaded" is exactly the state the certified button encodes.
