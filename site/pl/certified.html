Why it matters: taking a regular copy while the poświadczone button is enabled is a one-way loss of the strongest form of that document — the poświadczone pobierz cannot be re-obtained. A regular copy can never be turned into a poświadczone one. That is why the policy is "poświadczone first", and why /rejestr and /dostęp state each file's form (CERT / SRC / TEXT / PACK).

How each capture is traced through Windows telemetry

A file is evidence only if we can say when and from where it came. The station zapiss this from evidence the operating system keeps independently of our notes:

  1. The bajty — SHA-256, size, and the NTFS CreationTime / LastWriteTime.
  2. Zone.Identifier — the NTFS alternate data stream Chrome writes on pobierz. It carries the source URL and referrer, and is the closest thing to a receipt that the file came from jimspss1.courts.state.hi.us.
  3. Chrome pobierzs history — the live History SQLite database, queried for the file name (target path, start time, URL, referrer, received bajty, state).
  4. USN journal (where available) — survives browser-history clearing.

The zapis binds file → dokument → JIMS URL → pobierz time → browser row → hash, and is appended to TELEMETRY.jsonl by tools/ssot/pobierz_telemetry.ps1. A capture without telemetry is still evidence of the file, but it cannot prove when it was taken — and "already pobierzed" is exactly the state the poświadczone button enkods.
